# The PROVE Principles

The discipline is engine-agnostic: nothing below mentions any particular AI
model or agent framework. It binds *whatever* drafts the artifact — human or
machine.

## Definitions

- **Engine** — the production system that executes declarative logic over
  documents (rules engine, SQL/dbt layer, validation pipeline, alert engine).
- **Artifact** — one unit of candidate logic (a rule, a check, a scenario, a
  policy entry).
- **Expert** — the human whose approval gates deployment. The expert *binds*;
  everything else *advises*.
- **Corpus** — real production documents/records the engine can be run over.
- **Review/serving skew** — the condition where the evidence the expert
  reviewed was generated by a different computation than the one production
  executes. The failure PROVE exists to make unsatisfiable.

## P1 — Single implementation locus

An artifact's logic exists in exactly one place: the production repository, in
the production rule language (or as production engine code). No survey script,
notebook, or prompt may re-express its detection logic — *even "just to
explore."* A quick approximation that diverges on normalization, scoping, or
exclusion semantics produces evidence about the wrong behavior.

**Enforcement:** treat any re-implementation as a defect, whether or not a
divergence has been observed. Give agents no tool that would let them write a
standalone detector; making the undisciplined action *unavailable* beats making
it discouraged.

## P2 — Inactive-but-runnable staging

The engine must evaluate artifacts that are staged but not activated, emitting
their findings into a non-decision-bearing side channel. Activation state is
data (an allowlist entry, a toggle), not code.

This is the one architectural prerequisite. If your engine can't do this yet,
this is the retrofit to prioritize — everything else in PROVE is cheap once P2
holds.

## P3 — Production-path evidence

Every artifact shown to the expert — flagged documents, matched lines, rendered
messages, fire rates — is generated by executing the production engine over
production documents through the production parser. Record evidence
provenance: engine version, config version, corpus slice.

Corollary (**corpus governance**): evidence generation parses raw source
documents through the production path. Derived analytical extracts (cached
frames, columnar exports, spreadsheets-of-spreadsheets) are forbidden as
evidence sources.

Corollary (**engine-verbatim rendering**): the expert-facing evidence format is
frozen, and the violation message in the review sheet is byte-identical to what
production would display. "Cleaning up" engine output for reviewers
reintroduces a rendering layer that can skew.

## P4 — Refine in place

Expert feedback is applied as edits to the production artifact itself, followed
by regeneration of evidence through P3. There is never a "port the final
version over" step, because there is nothing to port from.

## P5 — Data-only activation

Promotion to production is a minimal, reviewable data change — one allowlist
entry — that alters finding *visibility*, not finding *computation*,
accompanied by a green regression suite. No agent may activate anything;
activation is a human-made, human-reviewed edit.

## The invariant

Under P1–P5, at every gate in the lifecycle, the behavior the expert reviewed
and the behavior production will execute are **the same computation** — not two
computations argued to be equivalent. Approval is sound by construction.

## Supporting rails (not principles, but non-negotiable practice)

- **Golden-fixture regression.** Every artifact carries should-fire fixtures
  with expected findings. The suite runs before and after any change; a red
  suite halts everything unconditionally.
- **Single-artifact change isolation.** No edit touches two artifacts. Diffs
  stay attributable; rollbacks stay one-line.
- **Bounded exploration.** Corpus sweeps have file caps and time caps. No
  unbounded scans.
- **Models advise, humans bind.** Advisory reviews (LLM councils, linters)
  issue GO / NO-GO / REVISE; only the expert's verdict is binding, and a
  NO-GO override requires a recorded rationale.

## Scope honesty

The discipline guarantees that *what was reviewed is what ships*. It does not
guarantee the review itself is good — an expert can approve a bad artifact,
samples can miss rare behaviors, a corpus slice can be unrepresentative. Those
are *visible* problems, addressable with sampling and second reviewers. Skew is
an *invisible* problem; that is why it gets an architectural solution rather
than a procedural one.
