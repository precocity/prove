# PROVE

**P**ropose → **R**un → **O**bserve → **V**erify → **E**nable

An agentic development framework for shipping machine-executed business logic —
compliance rules, data-quality checks, detection heuristics, alert conditions —
with expert approval that is sound *by construction*.

## The problem it solves

When an AI agent drafts logic fast and a human expert must approve it before it
ships, the default workflow is broken: the evidence the expert reviews is
generated by a *re-implementation* of the candidate logic (a notebook, a survey
script, a prompt), and only after approval is the logic ported into the
production engine. The two implementations diverge — they always do — and the
expert ends up approving behavior that never ships. This is **review/serving
skew**, the governance-layer twin of train/serve skew.

PROVE eliminates it architecturally:

| Principle | Meaning |
|---|---|
| **P1 — Single implementation locus** | Candidate logic exists in exactly one place: your production repo, in your production rule language. No shadow re-implementations, ever. |
| **P2 — Inactive-but-runnable staging** | Your engine evaluates staged artifacts and emits findings to a side channel without affecting decisions. Activation state is data, not code. |
| **P3 — Production-path evidence** | Everything the expert reviews is generated by the production engine over production documents. |
| **P4 — Refine in place** | Expert feedback edits the production artifact itself; evidence is regenerated through P3. There is no "port it over" step. |
| **P5 — Data-only activation** | Shipping = one reviewed data change (an allowlist entry), guarded by a green regression suite. |

The invariant: **the behavior the expert reviewed and the behavior production
executes are the same computation.** Nothing to prove equivalent, because there
is only one implementation.

## What's in the box

- **An agent crew** (8 roles, rename to taste): Orchestrator, Discovery,
  Drafter, Evidence, Refiner, Council, Tester, Tracker. Personas are markdown
  files with fill-in-the-blank domain knowledge — your AI coding assistant
  plays every role.
- **A lifecycle** with a bounded, measurable refinement loop: candidate →
  fixtures → advisory review → corpus scan → expert verdicts → refine →
  re-scan → converge (or escalate) → audit → data-only activation.
- **Deterministic rails** enforced by a thin, stdlib-only Python runner:
  resumable pipeline state, gate checks, halt-on-red-regression, bounded
  iteration, activation ceremony. Agents propose; the rails dispose.
- **An onboarding interview**: after install, your AI assistant interviews you
  about your domain, engine, corpus, and expert workflow, then configures
  everything.

## Install

```bash
npx prove-method install          # once published
# or, from a local checkout:
node PROVE/tools/install.js --dir /path/to/your/project
```

The installer asks which AI tools you use (GitHub Copilot, Claude Code, Cursor,
generic AGENTS.md) and which agent roles you want, then copies the framework
into `.prove/` in your project and wires up the tool-specific instruction
files.

Then open your project in your AI tool and say:

> Read `.prove/docs/ONBOARDING.md` and interview me to configure PROVE for
> this project.

## Requirements

- Node.js 18+ (installer only)
- Python 3.11+ (runner)
- A production engine that can evaluate staged-but-inactive artifacts — or the
  willingness to add that affordance. It is the one architectural prerequisite
  (P2), and it is the retrofit worth prioritizing.

## Fit test

PROVE fits your task if you can name three things:

1. **An engine** — production code that executes declarative logic over
   documents/records (a rules engine, a dbt/SQL layer, a validation pipeline).
2. **A binding expert** — a human whose sign-off gates deployment.
3. **A corpus** — real documents the engine can be run over to generate
   evidence.

Works for: carrier compliance rules, medallion-architecture data-quality
checks, clinical alert rules, AML detection scenarios, content-moderation
policies, tax logic. Does not fit: one-off analyses, tasks with no production
engine, logic with no human gate.

## Daily loop

```bash
python .prove/runner status       # what's in flight, what's next — run first, every session
python .prove/runner regression   # your golden-fixture suite, before and after any change
python .prove/runner start MyNewRule
python .prove/runner advance MyNewRule
python .prove/runner record MyNewRule --fire-rate 0.012 --fp-rate 0.08
python .prove/runner activate MyNewRule   # gate-checked, human-confirmed, data-only
```

Your AI assistant (as the Orchestrator) drives these commands for you; the
runner exists so the gates are enforced in code, not in prompt text.

## Provenance

PROVE generalizes a deployed multi-agent system for authoring insurance
compliance rules ("Review Without Skew: A Production-Execution Discipline for
LLM-Assisted Authoring of Compliance Rules") and shares its philosophy with
human-in-the-loop workflows like Netflix's `oci-agent`: scaffold the agent with
deterministic, production-grade tools; surface inspectable intermediate
artifacts; let humans bind and machines advise — then deploy the reliable
thing deterministically.
